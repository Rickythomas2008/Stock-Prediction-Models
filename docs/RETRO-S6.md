## 7. 本项目自身的复盘（做对了什么 / 做错了什么）

**做对的**
1. 先建评估协议再谈模型——否则后面所有数字都不可信；
2. 把「成本」做成可测项（0.152% 往返、3.65% 年化拖累），而不是写一句「注意成本」；
3. 合规先查清再设计（CSRC 2024 No.8 → 先报告后交易 → `broker_confirmed_at` 门）；
4. 每个 Sprint 都有「能变红」的证明，不靠自述。

**做错的**
1. 报告渲染凭数值大小猜格式（Sharpe 变百分比）——说明「看起来对」必须被测试锁死；
2. `sample_uniqueness` 先写了个常数假实现——**假实现比没有更危险**；
3. 纸面运行 12 日后现金耗尽却未报警——暴露「目标不随权益再平衡」的真实设计缺口；
4. 装 pyqlib 前没评估依赖规模，造成环境漂移。
