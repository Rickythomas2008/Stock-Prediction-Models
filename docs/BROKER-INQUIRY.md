# 券商量化接口书面询问模板

用途：取得**书面**答复后再决定是否入金、是否启用自动下单。口头承诺（「10 万就能开」）不作为决策依据。

发送方式建议：客户经理邮箱 / 券商官方在线客服工单，保留回执。**只认书面**。

---

## 致：＿＿＿＿证券 客户经理

本人拟在贵司账户（资金规模约 10 万元人民币）使用**自行开发的程序**进行 A 股日频量化交易：程序生成交易建议，**经本人人工确认后**由程序向贵司交易接口发送委托。为确认合规路径，请就以下 5 项给出**书面答复**：

### 1. 量化权限（QMT / miniQMT）开通门槛

- 开通门槛的具体数值是多少？
- 判定口径是**时点资产**还是**日均资产**（多少日）？
- 是否**同时开通 miniQMT（极简模式）**，还是仅提供完整版 QMT？
- 该门槛是贵司**正式公示政策**，还是可以个案审批？请注明政策文件或批复依据。

### 2. 环境与库限制

- 是否提供 **QMT 模拟盘（仿真）**？开通条件是什么？
- miniQMT/xtquant 允许的 **Python 版本**与**第三方库白名单**是什么？（例如是否允许 numpy / pandas / torch；是否会出现 `Forbidden: Module ... not in whitelist`）
- 是否限制**同一账户同时登录的客户端数量**（QMT 客户端与手机 App 并发）？

### 3. 程序化交易报告（逐项确认责任方）

依据《证券市场程序化交易管理规定（试行）》（证监会公告〔2024〕8 号，2024-10-08 施行）第 7、8 条：

- 报告由**客户提交、贵司核查后转报交易所**，还是由贵司代为填报？
- 需要客户提供哪些材料（账户信息 / 资金规模及来源 / 杠杆情况 / 策略类型与**最高申报速率、单日最高申报笔数** / **交易软件名称、版本号、开发主体** / 联络人）？
- 从提交到「贵司确认可交易」的**处理时限**是多少个工作日？
- 软件升级（版本号变更）是否需要**变更报告**？流程与时限？

### 4. 条件单定性

- 贵司 App 提供的**条件单 / 智能订单 / 网格交易**，是否被视为「客户程序化交易」而需要前述报告？
- 如不需要，请书面确认其属于**贵司系统功能**，客户仅做参数设置。

### 5. 费用与风控

- 佣金费率、**最低佣金**（元/笔）、是否收取**撤单费**或高频差异化费用？
- 单账户是否有**申报速率/笔数**的系统侧限制？

---

## 我方承诺（随函说明）

- 不使用任何**第三方外挂、模拟点击、UI 自动化**工具接入贵司客户端；
- 不将账户交由他人操作，不代他人交易；
- 程序在**未取得贵司确认前不发送任何委托**；
- 保留完整决策与委托日志，可按贵司要求提供。

## 收到答复后的判定表（内部使用）

| 项 | 通过条件 | 实际答复 | 结论 |
|---|---|---|---|
| 门槛 | 明确数值 + 口径 + 是否正式政策 | | |
| miniQMT | 明确是否开通极简模式 | | |
| 模拟盘 | 可开通 | | |
| 报告流程 | 责任方 + 材料清单 + 时限 | | |
| 条件单定性 | 书面确认是否需要报告 | | |
| 费用 | 最低佣金与撤单费明确 | | |

**任一关键项未书面明确 ⇒ 不进入 R4（自动下单），只执行 R1（决策单 + 人工下单）/ R2（条件单）。**

## 备选方案（若 10 万不满足任何券商门槛）

1. R1：决策单导出（CSV/JSON）→ 人工在 App 下单；
2. R2：把决策单转为券商条件单，执行机械化；
3. R3：QMT 模拟盘继续验证执行链（`xtquant` 代码与实盘一致）；
4. 补足资产后再申请 miniQMT（届时重新走本模板）。
